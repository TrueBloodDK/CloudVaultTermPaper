# RBAC-модель защищённого облачного хранилища

Документ описывает реализованную модель разграничения доступа. Его удобно
использовать как техническое описание для курсовой работы и как памятку при
добавлении новых сценариев доступа.

## Участники модели

В системе есть два уровня ролей: глобальная роль пользователя и роль внутри
конкретного отдела.

### Глобальные роли

| Роль | Назначение |
|------|------------|
| `system_admin` | Управляет пользователями, отделами, папками, файлами и назначением прав. |
| `security_admin` | Просматривает журнал аудита и контролирует события безопасности. |
| `user` | Работает с файлами и папками в пределах отделов и выданных разрешений. |

Администратор системы и администратор безопасности разделены специально:
администратор системы не является единственным контролёром безопасности, а
администратор безопасности не получает автоматического права управлять файлами.

### Роли внутри отдела

Пользователь может состоять в нескольких отделах одновременно. В каждом отделе
у него одна локальная роль:

| Роль | Назначение |
|------|------------|
| `head` | Руководитель отдела. Может управлять ресурсами отдела. |
| `member` | Сотрудник отдела. Получает базовый рабочий доступ к ресурсам отдела. |

Глобальная роль и роль в отделе независимы. Например, обычный пользователь
может быть руководителем бухгалтерии и рядовым участником проектной группы.

## Объекты доступа

RBAC применяется к двум типам ресурсов:

| Ресурс | Описание |
|--------|----------|
| Папка | Иерархический контейнер, может принадлежать отделу и иметь дочерние папки. |
| Файл | Зашифрованный объект хранения, лежит в папке или вне папки. |

Папки поддерживают наследование прав: право, выданное на родительскую папку,
применяется к дочерним папкам и файлам внутри них.

## Действия

Система использует единый набор действий:

| Действие | Смысл |
|----------|-------|
| `view` | Видеть ресурс в списке. |
| `read` | Читать метаданные или содержимое. |
| `download` | Скачивать файл. |
| `upload` | Загружать файл в папку. |
| `create` | Создавать объект. |
| `update` | Изменять объект. |
| `delete` | Удалять объект. |
| `share` | Передавать доступ другим субъектам. |
| `manage` | Управлять ресурсом, покрывает остальные управленческие действия. |
| `audit` | Просматривать события аудита. |

Для удобства некоторые действия покрывают более узкие операции. Например,
`read` покрывает просмотр, `download` даёт скачивание файла, а `manage`
покрывает управление ресурсом.

## Субъекты разрешений

Право можно выдать одному из трёх субъектов:

| Субъект | Пример |
|---------|--------|
| Конкретный пользователь | Дать Ивану право `download` на файл. |
| Весь отдел | Дать бухгалтерии право `read` на папку. |
| Роль внутри отдела | Дать руководителям отдела разработки право `share` на папку. |

Одно разрешение всегда относится только к одному субъекту: либо пользователь,
либо отдел, либо роль внутри отдела. Это проверяется моделью и ограничениями БД.

## Эффекты разрешений

Разрешение имеет эффект:

| Эффект | Смысл |
|--------|-------|
| `allow` | Разрешить действие. |
| `deny` | Запретить действие. |

`deny` нужен для исключений. Например, можно разрешить отделу скачивание папки,
но запретить конкретному пользователю скачивание одного файла или дочерней
папки.

## Порядок проверки доступа

Проверка доступа выполняется централизованно в `files/access.py`.

Для папок порядок такой:

1. `system_admin` или владелец папки получают доступ.
2. Проверяются явные права на текущую папку.
3. Если явных прав нет, проверяются права родительских папок.
4. Если папка привязана к отделу, применяется базовая роль отдела.
5. Если ни одно правило не сработало, доступ запрещается.

Для файлов порядок такой:

1. `system_admin` или владелец файла получают доступ.
2. Проверяются явные права на файл.
3. Проверяются унаследованные права папки.
4. Если файл лежит в папке отдела, применяется базовый доступ отдела.
5. Если ни одно правило не сработало, доступ запрещается и может быть записан
   отказ в журнал аудита.

## Наследование папок

Права папок наследуются от ближайшей папки к корню:

1. Сначала проверяется сама папка.
2. Затем её родитель.
3. Затем родитель родителя.

Ближайшее правило имеет приоритет. Это позволяет переопределить родительскую
политику на дочерней папке:

- родительская папка разрешает `download` отделу;
- дочерняя папка запрещает `download` конкретному пользователю;
- пользователь видит запрет именно на дочерней папке.

## Базовые права отдела

Если явные права не заданы, используется безопасный базовый режим:

| Субъект | Базовый доступ |
|---------|----------------|
| Член отдела | Просмотр, чтение, загрузка и создание в папках своего отдела. |
| Руководитель отдела | Управление ресурсами отдела: изменение, удаление, передача доступа. |

Явные правила `allow` и `deny` позволяют расширять или сужать этот базовый
доступ без изменения роли пользователя.

## Делегирование доступа

Пользователь не может выдать право, которым сам не обладает. Чтобы выдать
право на файл, должны выполняться оба условия:

1. У пользователя есть право `share` на файл или его папку.
2. У пользователя есть то действие, которое он пытается выдать.

Владелец файла и `system_admin` могут назначать права без этой дополнительной
проверки. Такое правило предотвращает ситуацию, когда пользователь с правом
передачи доступа выдаёт другим более высокий уровень доступа, чем имеет сам.

## Аудит

Критичные изменения RBAC записываются в журнал аудита:

| Событие | Когда записывается |
|---------|--------------------|
| `role_change` | Изменение глобальной роли или активности пользователя. |
| `department_assign` | Назначение, изменение или удаление членства в отделе. |
| `permission_grant` | Выдача или обновление права доступа. |
| `permission_revoke` | Отзыв права доступа. |
| `access_denied` | Отказ в доступе к защищённому ресурсу. |

Журнал аудита доступен администратору безопасности.

## Практические сценарии

### Сотрудник бухгалтерии получает доступ к папке отдела

1. Пользователь входит в отдел "Бухгалтерия" как `member`.
2. Папка привязана к отделу "Бухгалтерия".
3. Пользователь получает базовый доступ: просмотр, чтение, загрузка.
4. Удаление и передача доступа остаются недоступны.

### Руководитель отдела выдаёт доступ на файл

1. Пользователь состоит в отделе как `head`.
2. Файл лежит в папке этого отдела.
3. Руководитель имеет право `share`.
4. Он может выдать другому пользователю только то действие, которым обладает сам.

### Исключение через запрет

1. Отделу разрешён `download` на родительскую папку.
2. На дочерней папке конкретному пользователю задан `deny download`.
3. На дочерней папке запрет перекрывает родительское разрешение.
4. На остальных папках родительское разрешение продолжает работать.
